# guacamole_deploy

Deploys digest-pinned Guacamole, guacd, and PostgreSQL containers in one private
Podman pod. Only the web application is bound to the host (loopback by default);
guacd and PostgreSQL remain pod-internal. The official schema is generated by a
pinned init container and local break-glass credentials are supplied from Vault.
The role enables the PostgreSQL and OpenID Connect extensions explicitly,
preserves the local break-glass path, trusts proxy headers only through
Guacamole's Remote IP Valve, and reconciles inventory-declared RDP, SSH, or VNC
connections through the loopback-only Guacamole API.

OIDC is opt-in and requires all issuer, authorization, JWKS, and redirect
settings. The local break-glass hash is updated only when its Vault-custodied
password or salt has changed.

`guacamole_deploy_connections` is a list of connection contracts containing
`name`, `protocol`, `parameters`, optional `attributes`, and an optional
`parent_identifier`. Credentials do not belong in this list; keep them in Vault
or require users to supply them interactively.
